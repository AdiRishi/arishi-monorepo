## Install

Install Node.js 26 and enable Corepack, then install the workspace:

```sh
corepack enable
pnpm install
```

## Share the build cache

Turbo reads and writes a shared remote cache at `turbo-cache.adishwar-rishi.com`, configured under `remoteCache` in `turbo.json`. A task that already ran in CI or on another machine with the same inputs replays from the cache. Export the cache credentials in your shell profile:

```sh
export TURBO_TOKEN=<token>
export TURBO_REMOTE_CACHE_SIGNATURE_KEY=<signing key>
```

Turbo signs each upload with the key and rejects downloads without a valid signature, so every machine needs the same key. Without `TURBO_TOKEN`, Turbo prints `Remote caching disabled` and uses the local cache only.

## Run the application

From the repository root:

```sh
pnpm dev
```

Alchemy starts the web app and Worker graph in workerd. Open the web URL printed in the terminal.

On the first run, Alchemy may ask you to authenticate with Cloudflare to initialize its state store. Non-interactive configuration is documented in `infra/.env.example`.

Start development through Alchemy so the web app receives its Worker bindings. Running Vite directly in `apps/web` does not provide them. Internal packages export TypeScript source, so edits need no separate compilation step.

## Add application code

Keep the platform setup and add to it:

- `infra/src/worker-bindings.ts` and `infra/src/workers.ts`: declare resources, bind them, and add Workers. Declare databases, buckets, and queues in a module under `infra/src/` and pass them to the bindings.
- `workers/api/src/index.ts`: serve routes, cron, and RPC entrypoints. Give each caller its own `WorkerEntrypoint` and RPC group from `@repo/contracts`.
- `workers/api/vitest.config.ts` and `apps/web/vitest.config.ts`: give each new binding a stand-in.
- `infra/tests/integration/journeys/`: keep a journey for each main flow a person takes through the site.

Finish with `pnpm install`, `pnpm check`, `pnpm typecheck`, and `pnpm test`.

## Read and edit the docs

In a separate terminal:

```sh
pnpm docs:dev
```

Open the local URL printed by Blume. This server runs independently of the application and needs no Cloudflare credentials.

Edit pages in `docs/` as Markdown or MDX. Blume updates the browser as you save. `blume.config.ts` sets the site title and theme. Navigation follows the directory tree; `sidebar.order` in a page's frontmatter controls its position.

To check the content and generate a static site, stop the docs server and run:

```sh
pnpm docs:doctor
pnpm docs:build
pnpm exec blume preview
```

The static site is written to the root `dist/` directory. Blume's generated runtime lives in `.blume/`; both directories are ignored by Git.

See [Blume's authoring guide](https://useblume.dev/docs/content) for page syntax and components.
